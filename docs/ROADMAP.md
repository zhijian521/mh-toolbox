## 验收方式

1. `npm run check`：格式、ESLint、TypeScript、基线领域测试及独立存储测试。
2. `npm run build` 后 `npm run test:electron`：真实窗口/IPC 中验证首轮角色流程、回滚重试、草稿提醒、门派切换、历史、排序、刷新恢复、导入导出和清空。
3. `npm run verify`：把上面两步串成一次，提交前跑这条即可。
4. `npm run dist:dir`：生产资源、preload、字体与应用入口打包。
5. 使用临时 profile 的 `tests/inspect.electron.cjs` 检查实际窗口，示例数据不进入用户数据。
6. 每个后续模块开始前与结束前运行 `migration:status`，并记录已同步差异。

## 明确不做的事

写下来是为了避免每次重新讨论，不是因为做不到。

| 事项                            | 决定     | 理由                                                                                              |
| ------------------------------- | -------- | ------------------------------------------------------------------------------------------------- |
| 独立的 CHANGELOG                | 不维护   | 验收过程记在 `VALIDATION.md`，改动原因记在提交正文；再养一份变更日志只会与两者漂移                |
| 组件单测（vitest 等）           | 暂不引入 | 领域规则由 `tests/domain/` 覆盖，交互由 `tests/*.electron.cjs` 覆盖；页面数量再翻一倍时重新评估   |
| 提交钩子（husky / lint-staged） | 不安装   | 校验放在 CI（`scripts/check-commits.mjs`），本地按需 `npm run lint:commits`，避免钩子在沙箱里误报 |
