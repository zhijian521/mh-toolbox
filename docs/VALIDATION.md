**1. 物品记录也能删。** 记错一件、数量填错时，不必再进物品模块。`removeTransaction` 本来就成对处理：删物品会带走挂在它上面的成交记录（否则留下无主收入），删成交会把物品退回「持有」（`syncItem`）。所以这里只放开删除，**编辑仍然不给**——金额是「数量 × 单价」算出来的，改一个数字会绕过 `syncItem` 的约束。确认窗按类型换标题与说明：「删除物品记录」讲清会连带删几条成交、合计多少；「删除成交记录」讲清物品会回到持有。

**2. 收益实时同步，不等结束游戏。** 领域新增 `syncAccountEarnings(dates)`：对给定日期按角色算出「速记金币 + 物品估值 − 点卡（含正在计时那一段）」，写进账号账本的「游戏收益」。几个关键决定：

- **同一天同角色只留一条**：命中就原地改写，金额为 0 时把那条删掉——留一条 0 元记录只会让人以为当天记过账。

- **只算 `source === 'quick'`**：摆摊卖货那类成交收入属于账号里另记的账，混进来会和用户自己记的重复。
- **正负决定收支**：亏损写成支出，账号账本的 `income` 不接受负数。
- 写操作自己 `commit`，直接放进 `app.execute`；同步失败只提示、不回滚速记——账已经记上了，硬抛会让人以为白记。

**不做分次出售，改为按当前物价估值。** 原计划里「卖出才计入收入」要一整套成交流程（弹窗、数量上限、日期不早于获得日、剩余数量），而这份工具明确不做库存视图。这次把物品价值的口径从「记录时的单价」改成「当前参考单价」：改了物价表，历史记录的估值跟着变，不需要回头改任何一条流水。实现收在 `itemUnitPrice`（`data.js:217`）一处，`itemValue`、`stats`、`syncAccountEarnings` 与三个页面全部转发，避免第二份口径。

**空单元格表示「不改」，填 0 才清除。** 从导出的 CSV 里删掉几个数再导回来是很自然的操作，如果空单元格被当成 0，一次导入就能把没动的那些价悄悄清空。所以 `importItemPriceCsv` 把空值当保持原样，只有显式填 0 才 `delete`。这条边界在 `tests/domain/item-prices.test.cjs` 里有单独用例，改实现前先看那几个断言。

**单价表只覆盖固定价组。** 不固定价格的物品（书、铁、兽决…）每次点击现填、不写回单价表，导进来也会被下一次点击覆盖，写进去只会让人误以为生效了。导出时对全组都出一行、未设价的留空，用户看到的是完整清单而不是「改过的那几个」。

**目录拆出 `game-data/quick-catalog.js`。** `quick-items.js` 用 `import.meta.glob` 取图标 URL，是 Vite 专属语法；领域模块一旦 import 它，`npm test` 里 12 个文件会在加载阶段就报 `glob is not a function`。所以纯数据（id、名称、图标文件名）单独成文件，图片 URL 仍留在界面侧。

**主进程加的是通用文本通道，不是又一个专用接口。** `saveTextFile` / `openTextFile` 只负责挑路径、限体积（导入 8 MB）并落盘，内容由渲染层生成。与 `exportData` 的区别是那个写死了「整份 JSON 备份」的标题与过滤器，拿来导 CSV 会让用户以为要覆盖全部数据。导出仍套 `assertExportPath`：文件名填成 `data.json` 再选到数据目录，还是覆盖不了正在用的档案。

日期：2026-10-29。起因：① 单价表的两颗图标（纸 + 折角 + 箭头）在 16px 下折角糊成一团；② 标题右侧那行「记给 归岚（未计时）」是只读的，归属由代码里的隐式规则决定（计时中 → 当前筛选 → 第一个角色），用户既看不出怎么来的，也改不了——开两个号做师门、收益仍记在第一个号头上，就是这么来的。范围：`components/AppIcon.vue`（`download` / `upload` 两条路径）、`features/income/IncomePage.vue`。

**图标只留两笔。** 箭头占满高度、下面一道 14px 的落盘短线，两枚只差方向（导出朝下、导入朝上）。之前那版「纸 + 折角 + 箭头」的折角在 16px 下是一团黑点，而最早做的托盘造型又只剩一根横线、读起来像排序。实测尺寸：`svg` 16×16、按钮 26×24，两套主题下都不溢出。

**按钮边框从 `--line` 换成 `--line-2`。** 暗色下 `--line`（`#3a3427`）与卡片底色（`#201d16`）几乎同色，16px 的箭头会像两个裸箭头浮在卡面上；物品卡有图片自己成形，这两颗只有线条，必须靠边框收边。

**归属变成可以点的目标**（`target: 'auto' | 'all' | 角色 id`，默认 `auto`）：

- `auto` 跟随计时，记给正在计时的号；没在计时就记给全部。
- `all` 全部角色：金币均分，物品只记一条。
- 某个角色：这笔记给它一个人。

标题右侧那颗签显示的是**解析后的结果**（`青衫客` / `全部 4 个` / `归岚、青衫客`），点开是六项目录：跟随计时、全部角色，一条细线之后是逐个角色（等级 · 门派 · 计时中）。有号正在计时时签上亮一颗绿点。

**「全部」对物品只写一条**——数量拆不开，领域 `saveQuickLoot` 就是这么定的（`ledger.js:326-327`：`if (item && index > 0) return null`），归第一位。所以弹层里这一项的副标题写明「金币均分 · 物品记给第一位」，不能只写「全部」。

**提示改成按「实际写了几条」说。** 原来物品选了多号也报「A、B 均分」，实际只写一条归第一位——提示和数据对不上，是最难察觉的那种错。现在金币那条的金额取自写入结果（尾差在第一条，比自己算除法准），物品多目标时明确写「物品只记一条，归 归岚」。

**类名冲突踩了一次。** 绿点原本用 `.target-dot.live`，而端到端测试数「正在计时的号」用的是 `querySelectorAll('.live')`（顶部计时条），多出来一个点会让 `'单号计时中'` 那条断言拿到 2 —— 看起来像计时功能坏了。改名 `.ticking`。这是本仓库第二次撞类名（第一次是空位格子的 `.empty`），局部修饰一律用专属名。
