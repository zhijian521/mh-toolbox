# 配色令牌与暗色模式

本文承接 `UI_GUIDE.md` 的「视觉基座」，只管两件事：**颜色从哪里来**（令牌）与**怎么切换**（主题）。组件的外观、间距、焦点样式仍归 `UI_GUIDE.md`。

## 1. 现状与目标

动手前先把存量点清，成本全在硬编码上：

| 项                   | 现状                                                                                            | 影响                                   |
| -------------------- | ----------------------------------------------------------------------------------------------- | -------------------------------------- |
| 颜色令牌             | 15 个，全在 `assets/styles.css:19-33`（12 个颜色 + 3 个滚动条）                                 | 现成的挂载点                           |
| `:root` 里写死的     | `color: #5b5348`、`background: #f2ecdd`（`styles.css:15-16`）                                   | 必须并入令牌，否则暗色下根元素仍是浅底 |
| 硬编码十六进制       | 100 行 / 23 个文件（`styles.css` 26、`PriceCard` 10、`GoalCard` 9、`BaseDate` 7、`App.vue` 6…） | 主要工作量                             |
| `color-mix` / `rgba` | 28 行（`PriceCard` 占 20）                                                                      | **多数零成本**，见第 5 节              |
| 图标                 | `AppIcon.vue:55-58` 内联 SVG、`stroke="currentColor"`                                           | 零成本                                 |
| 物品图标             | `assets/images/online-record/*.png` 彩色实物图                                                  | 不用处理                               |
| 主进程               | `main.cjs:30` `backgroundColor: '#f2ecdd'`、`frame: false`                                      | 需同步，否则窗口首帧闪浅底             |
| 偏好通道             | 就是 `localStorage`，键名约定 `mh.*`（`domain/data.js:36`）                                     | 主题存 `mh.theme`，不必新开通道        |

目标：三档切换（跟随系统 / 浅色 / 深色）、两套配色、**颜色的唯一来源是令牌表**。任何组件里再出现的十六进制值都视为缺陷。

不做的事写在最后一节。

## 2. 令牌体系

### 2.1 用 `light-dark()`，不要写两份变量块

```css
:root {
    color-scheme: light dark;
    --bg: light-dark(#f2ecdd, #17150f);
    --paper: light-dark(#fbf7ec, #201d16);
    /* …每个令牌一行 */
}
:root[data-theme='light'] {
    color-scheme: light;
}
:root[data-theme='dark'] {
    color-scheme: dark;
}
```

为什么不用「`:root` + `:root[data-theme='dark']` 两份覆盖」：那样每个令牌要写两遍，改一处忘一处就出现两套主题悄悄分叉；`auto` 档还要再复制一遍 `@media (prefers-color-scheme: dark)`，等于三份。`light-dark()` 一份定义就能覆盖三档，`auto` 完全由浏览器判断，JS 不需要监听媒体查询。

依赖：Chromium 123+。Electron 38 是 Chromium 140，可用。

`color-scheme` 同时让原生控件跟着变（`select` 下拉、滚动条、输入光标、`<input type="date">` 弹层），这部分不写 CSS 也会正确。

### 2.2 现有 12 个颜色令牌

| 令牌        | 亮色      | 暗色      | 用途                   |
| ----------- | --------- | --------- | ---------------------- |
| `--bg`      | `#f2ecdd` | `#17150f` | 页面底                 |
| `--paper`   | `#fbf7ec` | `#201d16` | 卡片、弹窗、输入框底   |
| `--paper-2` | `#f5efdf` | `#262218` | 次级面：表头、悬停底   |
| `--panel-3` | `#ece3cc` | `#2e291e` | 三级面：分区底、禁用底 |
| `--ink`     | `#2f2a24` | `#e8e0cd` | 正文                   |
| `--muted`   | `#7b705f` | `#a09580` | 次要文字               |
| `--line`    | `#d9cfb6` | `#3a3427` | 常规分隔线             |
| `--line-2`  | `#c2b58f` | `#4d4534` | 强调边框、输入框边     |
| `--red`     | `#b33a3a` | `#d9706a` | 涨、错误、危险         |
| `--gold`    | `#a67c2e` | `#d2a44e` | 主强调、金额           |
| `--green`   | `#4a7c59` | `#7faf8c` | 跌、成功               |
| `--blue`    | `#3d5a6c` | `#8aa7b8` | 修炼、信息             |

滚动条三色（`--scrollbar-thumb/-hover/-active`）同步给暗色值，它们已经是令牌，只需补 `light-dark()`。

暗色不是反色，是**暖黑**：`#17150f` 带一点褐，为了保住"宣纸 + 墨"的气质。换成中性灰 `#1a1a1a` 整个应用会变成通用后台管理系统。

强调色必须提亮，不能沿用亮色值——`#b33a3a` 放在 `#201d16` 上对比度只有 **2.87**，正文级信息撑不住（实测见第 6 节）。

### 2.3 新增 4 个语义令牌

现在的 12 个都是色值名，缺"这个颜色是干什么用的"。暗色下最常翻车的就是这些手写值，先把它们收成令牌：

| 新令牌                      | 亮色                  | 暗色                  | 替换目标                                                        |
| --------------------------- | --------------------- | --------------------- | --------------------------------------------------------------- |
| `--hover`                   | `#fffdf6`             | `#262218`             | 卡片/列表悬停底（`PriceCard` 悬停、`App.vue:208` 的 `#eee4d3`） |
| `--shadow`                  | `#2f2a2414`           | `#00000059`           | 弹窗、toast 的投影（`App.vue:266` 等）                          |
| `--danger-bg` / `--warn-bg` | `#ead9c7` / `#eee4d3` | `#3a2622` / `#332c1f` | 错误与警告条底（`App.vue:193`、`:208`、`:124`）                 |
| `--on-accent`               | `#fff8e7`             | `#1a1610`             | 主按钮与徽章上的文字（`styles.css:242`）                        |

## 3. 切换机制

### 3.1 三档：跟随系统 / 浅色 / 深色

存在 `localStorage['mh.theme']`，取值 `auto | light | dark`，缺省 `auto`。

- `auto`：`<html>` 上不设 `data-theme`，由 `light-dark()` 跟着系统走。
- `light` / `dark`：设 `data-theme`，覆盖 `color-scheme`，所有 `light-dark()` 随之切换。

入口放设置页新增的「外观」分区（三选一），与备份/清空那种危险操作分开摆放。

### 3.2 首帧不能闪

在 `index.html` 里加内联脚本，**早于任何样式表渲染**读偏好并写到 `<html data-theme>`：

```html
<script>
    const theme = localStorage.getItem('mh.theme');
    if (theme === 'light' || theme === 'dark') document.documentElement.dataset.theme = theme;
</script>
```

放到 Vue 挂载后再设会先画一帧浅底再翻成深色，深色用户每次启动都会看到一次白闪。`main.cjs` 的 `ready-to-show` 已经做到"先渲染再显示"，所以只要这段脚本在首帧前生效，连窗口底色都看不到。

### 3.3 主进程

`main.cjs:30` 的 `backgroundColor: '#f2ecdd'` 是窗口在首帧前、以及缩放时露出的底色，要跟着主题走。做法：设置变更时由渲染进程经 preload 白名单推一个 IPC，主进程调 `win.setBackgroundColor(暗色 ? '#17150f' : '#f2ecdd')`。

`nativeTheme.themeSource` 可选项：设成 `dark` 能让原生右键菜单、`<select>` 弹层跟着变暗；但它**不影响** `light-dark()`（那是 `color-scheme` 的职责），所以它只是补丁，不能替代第 2 节的机制。

## 4. 硬编码收敛顺序

按"影响面 × 集中度"排，一次一个文件，不要一把梭：

| 批次 | 文件                                                           | 行数     | 说明                                                            |
| ---- | -------------------------------------------------------------- | -------- | --------------------------------------------------------------- |
| 第一 | `assets/styles.css`                                            | 26       | `.btn` / `.icon-button` / `.empty` / 表单基线，改这里等于改全站 |
| 第二 | `app/App.vue`                                                  | 6 (+4)   | 外壳、侧栏、toast、错误条                                       |
| 第三 | `features/prices/PriceCard.vue`                                | 10 (+20) | 全站颜色最密的组件，见第 5 节                                   |
| 第四 | `features/goals/GoalCard.vue`                                  | 9        | 进度色带与徽章                                                  |
| 第五 | `components/BaseDate.vue` / `BaseModal.vue` / `BaseSelect.vue` | 7/4/3    | 弹层与日历，暗色下最易漏                                        |
| 第六 | 其余 15 个文件                                                 | 各 1–6   | 逐个过                                                          |

每清完一个文件，`grep -n '#[0-9a-fA-F]\{3,8\}' <文件>` 必须为空（`styles.css` 的令牌定义区除外）。

## 5. 三个已经知道的坑

1. **8 位 alpha 色在暗底会发脏。** `PriceCard` 的 `#b33a3a12`、`#4a7c5912`、`#7b705f12`（涨跌徽章底）是把半透明黑叠在浅底上算出来的；叠到 `#201d16` 上会变成一团脏灰。改成 `color-mix(in srgb, var(--red) 18%, transparent)`——这样叠的是分类色本身，两套主题都成立。
2. **阴影会消失。** `box-shadow: 0 3px 12px #2f2a2414` 在暗底上完全看不见，"浮起来"的层次感没了。暗色改用 `--shadow`（更黑的 alpha）+ 保留 1px 描边，用描边接住层级。
3. **`color-mix(… transparent)` 在暗底是提亮。** 亮色下"往白里混"和"往透明里混"视觉接近，暗色下前者变暗、后者变亮，方向相反。`PriceCard` 有 20 处此类写法，必须逐个目视核对，不能只信代码。

另外两处看似安全其实要看一眼：`.btn.primary` 的 `#fff8e7` 字压在 `#a67c2e` 金底上（`styles.css:239-243`），暗色下金底会提亮到 `#d2a44e`，白字对比度掉到 2.5 以下，必须换成 `--on-accent` 的深色值。

## 6. 对比度红线

正文与正文级信息 ≥ **4.5:1**，大字（≥18px 或 ≥14px 粗体）、图标、边框 ≥ **3:1**，纯装饰（分隔线、底纹）不设下限但不得低于 1.2:1。

实测（WCAG 相对亮度公式）：

| 组合                        | 对比度   | 判定                                       |
| --------------------------- | -------- | ------------------------------------------ |
| 亮 `--ink` / `--bg`         | 12.06    | 通过                                       |
| 亮 `--muted` / `--bg`       | **4.12** | **不达标**（既存问题，见下）               |
| 亮 `--red` / `--paper`      | 5.48     | 通过                                       |
| 亮 `--gold` / `--paper`     | **3.54** | 仅够大字/图标，12px 正文不达标（既存问题） |
| 亮 `--green` / `--paper`    | 4.54     | 通过                                       |
| 暗 `--ink` / `--bg`         | 13.88    | 通过                                       |
| 暗 `--muted` / `--bg`       | 6.18     | 通过                                       |
| 暗 旧 `--red` / `--paper`   | **2.87** | 不达标，故暗色改用 `#d9706a`               |
| 暗 新 `--red` / `--paper`   | 5.19     | 通过                                       |
| 暗 新 `--gold` / `--paper`  | 7.34     | 通过                                       |
| 暗 新 `--green` / `--paper` | 6.74     | 通过                                       |
| 暗 新 `--blue` / `--paper`  | 6.65     | 通过                                       |
| 暗 `--line` / `--paper`     | 1.36     | 装饰，可接受                               |

**两条既存问题**：亮色的 `--muted`（4.12）与 `--gold`（3.54）本来就没到 4.5，这不是暗色引入的。做暗色时可以顺手把亮色这两处一起修（`--muted` 压到 `#6f6555` 左右即可过 4.5，`--gold` 作为正文色时改用 `--ink` 或加深到 `#8a6322`），但会牵动一批既有界面，建议**单独立项**，不要混在暗色改造里，否则回滚时两件事缠在一起。

验收方式：写一次性脚本（`%TEMP%`，不进仓库）遍历令牌对，按上面的公式断言；两套主题都跑一遍。

## 7. 分期与验收

| 期        | 内容                                                                                                                                     | 验收                                                                                                          |
| --------- | ---------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------- |
| 一 · 骨架 | 令牌从 15 个扩到 20 个（12 颜色 + 5 语义 + 3 滚动条）、`light-dark()` 双值、`:root` 两处写死色并入、首帧脚本、设置页外观分区、主进程底色 | 切到深色后，未清理的组件保持"能看"（浅色残留但不刺眼）；`prettier`/`eslint`/`vue-tsc`/`npm test`/`build` 全过 |
| 二 · 清账 | 按第 4 节六批清完 100 行硬编码                                                                                                           | 每批 `grep` 十六进制为零；两套主题各截一遍总览、物价、账号、设置 + 一个弹窗                                   |
| 三 · 打磨 | 第 5 节三坑、图表与空态、`--muted`/`--gold` 的亮色欠账（若一并做）                                                                       | 对比度脚本全绿；截图逐页目视                                                                                  |

**默认主题建议**：一期、二期默认固定 `light`，暗色作为手动可选项；三期打磨完再切成 `auto`。否则系统是深色的用户，会在前两期看到半成品暗色，第一印象就是"这个应用配色坏了"。

## 8. 明确不做

- 不做用户自定义配色 / 主题包。令牌是单一来源，开放自定义等于开放 100 处硬编码的例外。
- 不做按时间自动切换（日落后变暗）。多一个状态源，却没有对应收益。
- 不做高对比度主题。`forced-colors` 已有系统级处理（`styles.css:69-73`），另做一套是重复投入。
- 不在本期改令牌命名（`--red` → `--rise` 之类）。约 40 处引用要跟着动，混进暗色改造里会让 diff 无法审；等配色稳定后单独做。
