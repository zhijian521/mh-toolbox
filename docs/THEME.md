# 配色令牌与暗色模式

本文承接 `UI_GUIDE.md` 的「视觉基座」，只管两件事：**颜色从哪里来**（令牌）与**怎么切换**（主题）。组件的外观、间距、焦点样式仍归 `UI_GUIDE.md`。

## 1. 现状与目标

动手前先把存量点清，成本全在硬编码上：

| 项                   | 现状                                                                                            | 影响                                   |
| -------------------- | ----------------------------------------------------------------------------------------------- | -------------------------------------- |
| 颜色令牌             | 15 个，全在 `assets/styles.css:19-33`（12 个颜色 + 3 个滚动条）                                 | 现成的挂载点                           |
| `:root` 里写死的     | `color: #5b5348`、`background: #f2ecdd`（`styles.css:15-16`）                                   | 必须并入令牌，否则暗色下根元素仍是浅底 |
| 硬编码十六进制       | 100 行 / 23 个文件（`styles.css` 26、`PriceCard` 10、`GoalCard` 9、`BaseDate` 7、`App.vue` 6…） | 主要工作量                             |
| `color-mix` / `rgba` | 28 行（`PriceCard` 占 20）                                                                      | **多数零成本**，见第 5 节              |

目标：三档切换（跟随系统 / 浅色 / 深色）、两套配色、**颜色的唯一来源是令牌表**。任何组件里再出现的十六进制值都视为缺陷。

**改造后的状态**：令牌 23 个全在 `styles.css:19-52`；组件里的十六进制值从 100 行降到 18 行，且这 18 行都写在 `light-dark()` 里（令牌与物价卡片的分类色表），不再是裸值。`src/renderer` 里任意 `.vue` 再出现裸十六进制都算回归。

不做的事写在最后一节。

## 2. 令牌体系

### 2.1 用 `light-dark()`，不要写两份变量块

```css
:root {
    color-scheme: light dark;
    --bg: light-dark(#f2ecdd, #17150f);
    --paper: light-dark(#fbf7ec, #201d16);
    /* …每个令牌一行 */
}
:root[data-theme='light'] {
    color-scheme: light;
}
:root[data-theme='dark'] {
    color-scheme: dark;
}
```

为什么不用「`:root` + `:root[data-theme='dark']` 两份覆盖」：那样每个令牌要写两遍，改一处忘一处就出现两套主题悄悄分叉；`auto` 档还要再复制一遍 `@media (prefers-color-scheme: dark)`，等于三份。`light-dark()` 一份定义就能覆盖三档，`auto` 完全由浏览器判断，JS 不需要监听媒体查询。

依赖：Chromium 123+。Electron 38 是 Chromium 140，可用。

`color-scheme` 同时让原生控件跟着变（`select` 下拉、滚动条、输入光标、`<input type="date">` 弹层），这部分不写 CSS 也会正确。

### 2.2 颜色令牌

| 令牌        | 亮色      | 暗色      | 用途                       |
| ----------- | --------- | --------- | -------------------------- |
| `--bg`      | `#f2ecdd` | `#17150f` | 页面底                     |
| `--paper`   | `#fbf7ec` | `#201d16` | 卡片、弹窗、输入框底       |
| `--paper-2` | `#f5efdf` | `#262218` | 次级面：表头、悬停底       |
| `--panel-3` | `#ece3cc` | `#2e291e` | 三级面：分区底、禁用底     |
| `--ink`     | `#2f2a24` | `#e8e0cd` | 标题                       |
| `--ink-2`   | `#5b5348` | `#cfc6b2` | 正文默认色（比标题浅一档） |
| `--muted`   | `#7b705f` | `#a09580` | 次要文字                   |
| `--line`    | `#d9cfb6` | `#3a3427` | 常规分隔线                 |
| `--line-2`  | `#c2b58f` | `#4d4534` | 强调边框、输入框边         |
| `--red`     | `#b33a3a` | `#d9706a` | 涨、错误、危险             |
| `--gold`    | `#a67c2e` | `#d2a44e` | 主强调、金额               |
| `--green`   | `#4a7c59` | `#7faf8c` | 跌、成功                   |
| `--blue`    | `#3d5a6c` | `#8aa7b8` | 修炼、信息                 |

`--ink-2` 原来不是令牌：`:root` 直接把 `color: #5b5348` 写在属性上。它不是 `--ink`（标题用），而是成段文字的默认色，比标题浅一档——所以单独给一个令牌，而不是把 `--ink` 调浅，否则标题会一起变灰。

滚动条三色（`--scrollbar-thumb/-hover/-active`）同步给暗色值，它们已经是令牌，只需补 `light-dark()`。

暗色不是反色，是**暖黑**：`#17150f` 带一点褐，为了保住"宣纸 + 墨"的气质。换成中性灰 `#1a1a1a` 整个应用会变成通用后台管理系统。

强调色必须提亮，不能沿用亮色值——`#b33a3a` 放在 `#201d16` 上对比度只有 **2.87**，正文级信息撑不住（实测见第 6 节）。

### 2.3 语义令牌

现有的都是色值名，缺"这个颜色是干什么用的"。暗色下最常翻车的就是这些手写值，先把它们收成令牌：

| 新令牌                      | 亮色                  | 暗色                  | 替换目标                                    |
| --------------------------- | --------------------- | --------------------- | ------------------------------------------- |
| `--hover`                   | `#fffdf6`             | `#262218`             | 卡片/列表悬停底                             |
| `--shadow`                  | `#2f2a2414`           | `#00000059`           | 弹窗、toast 的常规投影                      |
| `--shadow-lg`               | `#2f2a242e`           | `#00000080`           | 下拉弹层那种更大范围的投影                  |
| `--overlay`                 | `#2f2a2445`           | `#000000a6`           | 弹窗遮罩（**不能混 `--ink`**，见第 5 节末） |
| `--danger-bg` / `--warn-bg` | `#ead9c7` / `#eee4d3` | `#3a2622` / `#332c1f` | 侧栏选中项、悬停项这类"淡色面"              |
| `--on-accent`               | `#fff8e7`             | `#1a1610`             | 主按钮、金色底上的文字                      |

## 3. 切换机制

### 3.1 三档：跟随系统 / 浅色 / 深色

偏好由**主进程**持有，存在 `userData/preferences.json` 的 `{ "theme": "auto" }`，取值 `auto | light | dark`，缺省 `auto`。

为什么不放 `localStorage`：主题必须在**创建窗口之前**就定下来，而渲染进程的 `localStorage` 要等页面跑起来才读得到。放进主进程顺带解决了这点。

### 3.2 用 `nativeTheme.themeSource`，不写防闪脚本

```js
nativeTheme.themeSource = preference === 'auto' ? 'system' : preference;
```

`themeSource` 会改变渲染进程 `prefers-color-scheme` 的求值结果，`light-dark()` 随之一并切换——首帧天然正确，页面里不需要任何"读偏好再设属性"的引导脚本。

原本的计划是 `index.html` 里塞一段内联脚本设 `<html data-theme>`，实测行不通：`index.html` 的 CSP 是 `script-src 'self'`，内联脚本直接被拦。要走 `data-theme` 那条路就得给 CSP 开 `'unsafe-inline'`，为一个主题放松脚本策略不划算。

`main.cjs` 的 `ready-to-show` 本来就是"渲染完再显示"，所以窗口也不会有白闪的前置帧。

### 3.3 主进程侧的两处联动

`src/main/theme.cjs` 负责读写偏好与应用 `themeSource`，并给窗口底色：

- `backgroundColor` 不能再写死 `'#f2ecdd'`，改由 `theme.background()` 给（`light-dark` 的两个 `--bg` 值就是这里的两个常量）。
- 切主题时同时 `win.setBackgroundColor()`——只改 `themeSource` 会让界面变暗、但缩放窗口时闪一下浅底。
- 监听 `nativeTheme.on('updated')`：`auto` 档下 Windows 换主题，窗口底色要跟着走。

### 3.4 切换入口

设置页「外观」分区，三选一按钮组（`.btn` + `.btn.selected`），走 `mhV2.getTheme / setTheme` 两个白名单通道。切换即时生效，不重载页面。

## 5. 三个已经知道的坑

1. **8 位 alpha 色在暗底会发脏。** `PriceCard` 的 `#b33a3a12`、`#4a7c5912`、`#7b705f12`（涨跌徽章底）是把半透明黑叠在浅底上算出来的；叠到 `#201d16` 上会变成一团脏灰。改成 `color-mix(in srgb, var(--red) 12%, transparent)`——这样叠的是分类色本身，两套主题都成立。
2. **阴影会消失。** `box-shadow: 0 3px 12px #2f2a2414` 在暗底上完全看不见，"浮起来"的层次感没了。暗色改用 `--shadow`（更黑的 alpha）+ 保留 1px 描边，用描边接住层级。
3. **`color-mix(… transparent)` 在暗底是提亮。** 亮色下"往白里混"和"往透明里混"视觉接近，暗色下前者变暗、后者变亮，方向相反。`PriceCard` 有 20 处此类写法，必须逐个目视核对，不能只信代码。

还有一处逆向的坑：**遮罩不能跟 `--ink` 走**。`#2f2a2445` 看着像"墨色半透明"，直接换成 `color-mix(in srgb, var(--ink) 27%, transparent)` 在暗色下会把背景提亮成一团灰雾——暗色的 `--ink` 是浅色。所以单独给了 `--overlay`。

**唯一允许的固定色**：`EquipmentScreenshotDialog` 的角标与删除按钮（`#2f2a24bf` / `#f6f1e7` 等 6 处）。它们叠在用户的游戏截图上看，截图明暗不可控，浮层只有固定深底浅字才保证任何截图上都读得出来，跟主题走反而会坏。

另外两处看似安全其实要看一眼：`.btn.primary` 的 `#fff8e7` 字压在 `#a67c2e` 金底上（`styles.css:239-243`），暗色下金底会提亮到 `#d2a44e`，白字对比度掉到 2.5 以下，必须换成 `--on-accent` 的深色值。

## 6. 对比度红线

正文与正文级信息 ≥ **4.5:1**，大字（≥18px 或 ≥14px 粗体）、图标、边框 ≥ **3:1**，纯装饰（分隔线、底纹）不设下限但不得低于 1.2:1。

实测（WCAG 相对亮度公式）：

| 组合                        | 对比度   | 判定                                       |
| --------------------------- | -------- | ------------------------------------------ |
| 亮 `--ink` / `--bg`         | 12.06    | 通过                                       |
| 亮 `--muted` / `--bg`       | **4.12** | **不达标**（既存问题，见下）               |
| 亮 `--red` / `--paper`      | 5.48     | 通过                                       |
| 亮 `--gold` / `--paper`     | **3.54** | 仅够大字/图标，12px 正文不达标（既存问题） |
| 亮 `--green` / `--paper`    | 4.54     | 通过                                       |
| 暗 `--ink` / `--bg`         | 13.88    | 通过                                       |
| 暗 `--muted` / `--bg`       | 6.18     | 通过                                       |
| 暗 旧 `--red` / `--paper`   | **2.87** | 不达标，故暗色改用 `#d9706a`               |
| 暗 新 `--red` / `--paper`   | 5.19     | 通过                                       |
| 暗 新 `--gold` / `--paper`  | 7.34     | 通过                                       |
| 暗 新 `--green` / `--paper` | 6.74     | 通过                                       |
| 暗 新 `--blue` / `--paper`  | 6.65     | 通过                                       |
| 暗 `--line` / `--paper`     | 1.36     | 装饰，可接受                               |

**两条既存问题**：亮色的 `--muted`（4.12）与 `--gold`（3.54）本来就没到 4.5，这不是暗色引入的。做暗色时可以顺手把亮色这两处一起修（`--muted` 压到 `#6f6555` 左右即可过 4.5，`--gold` 作为正文色时改用 `--ink` 或加深到 `#8a6322`），但会牵动一批既有界面，建议**单独立项**，不要混在暗色改造里，否则回滚时两件事缠在一起。

验收方式：写一次性脚本（`%TEMP%`，不进仓库）遍历令牌对，按上面的公式断言；两套主题都跑一遍。

| 期        | 内容                                                                                                                                                                    | 验收                                                                                  | 状态   |
| --------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------- | ------ |
| 一 · 骨架 | 令牌 15 → 23 个（13 颜色 + 7 语义 + 3 滚动条）、`light-dark()` 双值、`:root` 两处写死色并入、`preferences.json` + `nativeTheme.themeSource`、设置页外观分区、主进程底色 | 深色启动即是深色、切档即时生效；`prettier`/`eslint`/`vue-tsc`/`npm test`/`build` 全过 | 已完成 |
| 二 · 清账 | 按第 4 节六批清完 100 行硬编码（实清 82 行，18 行是令牌里的 `light-dark` 值）                                                                                           | `src/renderer` 里除令牌区与分类色表外无十六进制；两套主题逐页截图                     | 已完成 |
| 三 · 打磨 | 第 5 节三坑的细节、空态与小控件的目视校正、`--muted`/`--gold` 的亮色欠账（若一并做）                                                                                    | 对比度脚本全绿；逐页目视                                                              | 待做   |

**默认主题目前是 `auto`**（跟随系统）。原本计划在一、二期先固定 `light`、打磨完再放开，实际两期一次做完，暗色在各页已经过扫描（见下），所以直接给了 `auto`；如果发现哪页还有残留，改 `theme.cjs` 的缺省值即可回退。

**验收方式上的一个实操**：判断"暗色有没有漏"不要靠眼睛扫，跑一个临时脚本遍历所有可见元素，把 `backgroundColor` 亮度 > 0.5、alpha ≥ 0.6、面积 ≥ 1200px² 的列出来。八个页面扫下来只剩金色主按钮（`.btn.primary`，暗色下本来就该亮），比逐页目视可靠得多。

## 8. 明确不做

- 不做用户自定义配色 / 主题包。令牌是单一来源，开放自定义等于开放 100 处硬编码的例外。
- 不做按时间自动切换（日落后变暗）。多一个状态源，却没有对应收益。
- 不做高对比度主题。`forced-colors` 已有系统级处理（`styles.css:69-73`），另做一套是重复投入。
- 不在本期改令牌命名（`--red` → `--rise` 之类）。约 40 处引用要跟着动，混进暗色改造里会让 diff 无法审；等配色稳定后单独做。
